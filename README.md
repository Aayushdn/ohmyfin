# ohmyfin
> **Currently in development.** I'm building this in the open, so features are still being added. See [Status](#status) for what's next.

A personal finance tracker for iOS and Android, built with React Native and Expo. Track income and expenses, organise them into categories, and set spending budgets. Your data lives in a SQLite database on your phone, so the app works fully offline. You can use it as a guest, or sign in with an account.

## What it does

- **Local first.** Everything is stored in an on-device SQLite database. No account is needed to start.
- **Guest or account.** Choose "Continue locally" to start straight away, or sign up and log in with Supabase. A guest can create an account later and keep all of their data.
- **Quick onboarding.** A short step-by-step setup asks for your name and currency, lets you pick or add spending and income categories, and optionally sets up a budget.
- **Categories.** Income and expense categories with sensible defaults you can keep, remove, or extend.
- **Budgets.** A budget has a name and a period, with one rule per category: a spending limit and an optional "warn me at" amount.
- **Exact money.** Amounts are stored as whole cents in integer columns, so there are no floating-point rounding errors.

## How it works

**Data.** The schema in [`src/db/schema.ts`](src/db/schema.ts) defines six tables: `users`, `categories`, `transactions`, `recurring_transactions`, `budgets` and `budget_rules`. Migrations are generated by Drizzle Kit into [`drizzle/`](drizzle), bundled into the app, and applied automatically each time the app starts. Updating the app on a phone upgrades its database in place.

**Navigation.** The root layout runs the migrations first, then uses protected route groups to decide what a user can see:

| User state | Can open | Lands on |
| --- | --- | --- |
| New, or onboarding unfinished | `onboarding`, `auth` | Welcome screen |
| Onboarded guest | `(app)`, `auth` | Tabs |
| Onboarded with an account | `(app)` | Tabs |

**Guest to account.** A guest is a local `users` row with no `auth_id`. Signing up links the Supabase user id to that same row, so existing categories, transactions and budgets stay attached.

## Getting started

### Prerequisites

- Node.js 20 or newer
- [pnpm](https://pnpm.io)
- Xcode (iOS) or Android Studio (Android) to run a development build
- A free [Supabase](https://supabase.com) project

### Install and run

```bash
git clone https://github.com/Aayushdn/ohmyfin.git
cd ohmyfin
pnpm install
```

Create a `.env` file in the project root with your Supabase project values:

```bash
EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
EXPO_PUBLIC_SUPABASE_KEY=your-anon-public-key
```

Both are required, because the Supabase client is created when the app starts. Use the public anon key, never a service-role key.

Then build and launch a development build (the project uses `expo-dev-client` and native modules):

```bash
pnpm android   # or: pnpm ios
```

After the first build you can start only the dev server with `pnpm start`.

### Resetting local data

Uninstall the app from the simulator or device to wipe its database. In development builds the floating dev menu also offers shortcuts to clear the session, reset onboarding, or delete the local profile.

## Working with the database

After changing `src/db/schema.ts`, generate a new migration and commit the result:

```bash
pnpm db:generate
```

Review the new SQL file in `drizzle/` before committing. Don't edit or delete a migration after it has shipped, because devices that already applied it won't run it again. Add a new one instead.

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm start` | Start the Expo dev server |
| `pnpm android` / `pnpm ios` | Build and run a development build |
| `pnpm web` | Start the web target |
| `pnpm lint` | Run ESLint |
| `pnpm db:generate` | Generate a Drizzle migration from the schema |

## Project structure

```
src/
├── app/            Expo Router screens: onboarding, auth, and the (app) tabs
├── components/     Shared UI, including the onboarding wizard
├── context/        Auth and profile providers
├── data/           Database queries and writes (no UI code)
├── db/             SQLite client and Drizzle schema
├── hooks/          Theme and colour-scheme hooks
└── utils/          Supabase client
drizzle/            Generated SQL migrations
```
